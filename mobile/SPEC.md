> 状态：**已定稿**（原型 v2 经真机迭代验收，2026-10-21）
> 配套原型：`mobile/prototype2/index.html` · https://lab.ianonai.work/tech/hlb-mobile-ui2/

## 变更说明（v1 → v2）

v1 的真机第一版"能跑但 UI 不满意"，本版按 BtMule/GoMule 式交互全面重设计：

1. 装备展示由**纵向列表**改为**人形纸娃娃**（角色与佣兵都是），槽位坐标复用桌面版 `Equipment.tsx` 的 DOLL 定义。
2. 角色页由三段切换平铺改为**子页 + 一屏固定**（去掉长滚动页，解决滚动与拖动手势冲突）；新增**属性子页**。
3. 新增**拖放**（v1 明确排除，本版为核心交互）与**装备托盘**（跨页中转、落盘持久）。
4. 保存模型定案：**实时保存**（v1 未定义；桌面是手动保存，移动端刻意不同）。
5. 第 4 个 Tab 由"同步"改为"**设置**"，同步功能折入设置（本版只预留结构）。
6. 金币从"展示条"升级为可操作的**四账户转移**（含宝库金池）。

## 1. 背景与目标

- 同 repo 双入口、core 共享（`mobile-entry` 分支）：`src/core` 与 `src/state/store.ts` 零改动复用；移动端只做新前端入口 `mobile/`。
- 产品定位：**随身仓库管理**。iOS 上没有 D2R 本体，App 负责随时随地看装备、整理仓库与宝库、导入导出。
- 本 SPEC 只覆盖 UI/交互与前端状态策略；iOS bring-up（Rust stub、签名、`make ios` 直建 xcodebuild 流程）已于 2026-10-21 真机跑通，不在本 SPEC 范围。

## 2. 平台约束（iOS，不可违反）

| 约束 | 做法 |
|---|---|
| 沙盒：不能写 D2R Mobile 容器 | 存档"考进考出"：App 自己的 Documents 为工作区（`UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace`），经文件 App 中转 |
| 导出 `.d2i` | Rust `export_item` 写 App 的 `Documents/exports/`（沙盒内，无需 security-scoped 授权），用户在文件 App 挪走；系统分享直达为 v1.1 可选升级 |
| 无意义的桌面命令 | `is_game_running` → iOS 恒 false；`reveal_backups` → iOS 返回 Err；`art_detect_installs` → iOS 返回空，改走"用户亲手拷资源包"（均已实装） |
| updater | 桌面独占插件，iOS 上隐藏一切更新 UI |
| D2R Mobile 的存档布局 | 文件夹嵌套（`David/David.d2s`），`save_files` 已支持扫描一层子目录 |

## 3. 设计原则

1. **一屏固定**：除属性页（无可拖物品，允许滚动）与宝库列表外，每个页面内容一屏显示完、无滚动条——这是拖动手势成立的前提。
2. **手势三件套**：单击（属性面板）/ 双击（入·出托盘）/ 按住移动（拖放）。判别：拖动阈值 9px；单击带 ~250ms 双击判别窗。
3. **托盘是唯一的跨页运输**：跨 Tab、跨子页的移动一律经托盘或物品面板的"移动到…"，页内移动用拖放。
4. **实时保存是地基**（见 §8）：与托盘同为**常开基础行为，设置里不提供开关**——关掉任何一个，功能链就不完整。
5. **格子尺寸对齐游戏**：网格/槽位格 28px（iPhone 逻辑宽基准），即 D2R 手机端运行时的图标量级；小于 44pt 触控准则是刻意取舍（靠拖动阈值 + 双击判别兜底）。
6. **质感与桌面端一致**（见 §4），不能是"另一个 App 的感觉"。
7. **校验 reason 必须透出**：core 的移动/装备校验失败原因（如腰带规则、佣兵武器规则）用 Toast 原样展示，不静默失败。

## 4. 视觉系统（取自桌面版源码配方，不得自创）

源：`src/index.css`、`tailwind.config.js`；原型 v2 已按此实现。

- **石材面板**：噪点 + 深石渐变；**物品格**：暗靛蓝 `#17123f`
- **圆角**：移动端统一 2px
- **金色**：渐变 `#d4b66a→#9c7a34`；标题 Cinzel（离线回退 Georgia）
- **品质色**：unique `#c7b377` / set `#1fdc1f` / magic `#6969ff` / rare `#ffff64` / rune `#ffa033`
- **纸娃娃背板**：人形剪影（深石底 + 金色描边微光），槽位按桌面 DOLL 坐标以格为单位绝对定位（格 = 28px，`px(v) = v × (格 + 1.5)`）

## 5. 信息架构

底部 4 Tab：**角色 / 仓库 / 宝库 / 设置**。全局状态：**当前角色**（角色页与仓库页共享）。

### 5.1 角色 Tab
- 角色卡片列表（头像/名/等级职业/携带金币）→ 点入角色详情。
- 详情顶部子页签：**属性 / 装备 / 佣兵**。

#### 5.1.1 装备子页（一屏固定，本版核心页）
自上而下两组、两端对齐分布（剩余空间只在中间留一条）：
- **娃娃组**：人形纸娃娃（10 槽：头/颈/主手/躯干/副手/腰带/手套/双戒/靴，坐标同桌面 DOLL）；**主副手 I/II 切换为娃娃右上角浮层按钮**（不单独占行）；下方一行 = **腰带条 + 金币合并行**：左为腰带最下排 4 格 + "展开 N 排"按钮（展开为浮层，排数由所穿腰带 `beltBoxes` 决定：4/8/12/16 格 = 1–4 排），右为携带金币（点开金币转移 Sheet，见 §9）。
- **背包组**（贴底）：网格区 + [背包 | 方块] 切换芯片。背包 10×4；方块 **3 宽 × 4 高**（以 core `GRID_SIZE` 为准）。
- 页内拖放全通：娃娃 ↔ 背包 ↔ 腰带 ↔ 方块视图之间。

#### 5.1.2 属性子页（允许滚动，只读）
- 人物属性：生命/法力/耐力；力/敏/体/精（自身值 + 装备加成，分开标注）；四系抗性。
- 技能：按技能树分组，每技能显示总点数（基础点 + 装备加成，分开标注）。
- **装备加成汇总（隐藏属性）**：可加总项（抗性、MF、FCR、FHR、+技能按树汇总等）求和展示；触发/光环/充能类只罗列。
- **背包护符加成**单独成组（护符在背包内按游戏规则生效，口径与装备分开）。
- 属性/技能**修改**为后续版本功能，本版只读，数据通路不预先堵死。

#### 5.1.3 佣兵子页（一屏固定）
- 佣兵信息（名/类型/等级/光环）；佣兵纸娃娃（头/躯干/武器[/盾]，坐标同桌面 MERC_WORN + 副手位）；下方带**角色背包条**，支持背包 ↔ 佣兵槽拖放换装。
- 未雇佣时显示空状态；佣兵不可用的槽位（如二幕佣兵的盾位）灰显并标注。
- 佣兵槽位规则走 `core/merc.ts`，拖错 Toast 展示 reason。

### 5.2 仓库 Tab（一屏固定）
- 顶部角色切换条（切换"当前角色"）；分段切换 **[个人仓库 | 共享仓库]**。
- 个人：个人仓库网格 10×10 + 仓库金币行（`goldbank`）。
- 共享：页签 I–VII chips + 共享网格 10×10 + **共享金币只显示一处总数**（RotW 金币全页签共用一池，`goldPooled`，不得每页签各显示一份）。

### 5.3 宝库 Tab（列表，可滚动）
- 搜索框 + 品质 chips + 类型 chips + 筛选 Sheet。
- **筛选一期范围**（参考 GoMule，先做这些）：文本（名/底材）、品质、类型、需要等级区间、带凹槽、无形。**二期**：属性条件构建器（某属性 ≥/≤ X 的条件行组合）。
- 列表行：图标 + 名（品质色）+ 底材/类型/等级；单击开物品面板，双击入托盘取出。
- 宝库金池行：按 `goldPot`（版本 × HC/SC）分池展示（见 §9），一期可转。

### 5.4 设置 Tab（本版只预留结构）
条目：存档同步（考进考出，含来源说明与状态）、美术资源包（导入状态）、备份管理、关于。
**不得出现**：托盘开关、实时保存开关（见 §3.4）。

## 6. 手势与拖放

- **单击**物品 → 底部物品面板（§7.3）；**双击** → 托盘出入（§7.2）；**按住移动 >9px** → 拖放。
- 拖放合法性：槽位看 `fit`/bodyLoc 与 core `equip.ts` 规则（含：**腰带上层有药水时不能换/脱腰带**；新腰带容量须 ≥ 已用排数）；网格看 `Occupancy`/`findSpot` 占用与边界；佣兵看 `core/merc.ts`。
- 拖放反馈：合法目标绿框、非法红框 + 松手后 Toast reason；槽位被占用且可对换时（来源同为槽位且对方 fit 本槽）允许**对换**，否则拒绝。
- 拖放只存在于一屏固定页（装备/佣兵/仓库）；宝库列表滚动，不做拖出（走双击/面板入托盘）。
- 属性页无可拖物品，滚动与手势不冲突。

## 7. 装备托盘

### 7.1 存储与定位
- 托盘 = App 私有的一个 **vault 格式文档**（存 App Documents），列表模型、容量不限；托盘移动**双边实时落盘**（见 §8），放进来即可直接退出 App。
- 托盘物品不属于任何角色，游戏读不到；UI 文案须讲清（托盘抽屉内常驻说明）。
- 入口：右侧边缘把手（带数量角标），任意 Tab 可开（抽屉滑出）。

### 7.2 出入规则
- **双击**任意物品 → 入托盘；**双击托盘内物品 → 只落网格区**（当前屏的背包/方块/个人仓库/共享仓库，经 `findSpot`），**不判断装备槽**（刻意简化）；放不下 Toast 说明。
- **拖出托盘**：按住托盘物品拖动，**托盘自动收起**露出完整画面；落到合法位置（**含装备槽**）即放置；**落空则物品回托盘、托盘自动重新展开**（展开本身即回滚反馈）。
- **拖入托盘**：在任意页拖动物品时，右侧把手变为投放区（高亮），松手即入托盘。
- 物品面板内有"放入托盘"按钮（无手势门槛的兜底路径）。

### 7.3 物品面板（单击弹出）
内容：名（品质色）、底材、属性行、镶嵌物/符文之语、需要等级、所在位置。
操作：放入托盘（主按钮）/ **装备到空槽**（物品可装备且存在空 fit 槽时出现；被占则提示走拖放对换）/ 移动到…（目标 = 背包/方块/个人仓库/共享仓库/宝库/托盘）/ 导出 .d2i / 删除（真实版须二次确认）。

## 8. 保存模型（与桌面刻意不同）

- **实时保存，常开，无开关、无保存按钮**。理由：移动端 App 随时可能被系统杀死；"放进托盘就退应用"是既定用法，攒批保存必然丢/重复物品。
- 每次变更后防抖 ~500ms 写盘（原子写已有）；**写前自动备份**（滚动保留，备份管理在设置页）；提供全局**撤销**兜底手滑。
- 顶栏常驻保存状态（绿点 + "已保存 HH:MM"）。
- 托盘文档与来源文档在同一次变更里一起落盘，保证双边一致。

## 9. 金币

- 四个账户：**携带**（`stats.gold`）/ **个人仓库**（`stats.goldbank`）/ **共享仓库金池**（RotW 全页签一池）/ **宝库金池**（`goldPot`，按版本 × HC/SC 分池）。
- 转账走现成 `store.transferGold(from, to, amount)`；上限走 `goldCap(ref)`。
- 交互：点任意金币行 → 转移 Sheet（来源固定为该行账户；目标 chips；金额输入 + "最大"；显示目标余额/上限/还可存；确认时金额 clamp 到 `min(来源余额, 目标剩余上限)`，不静默失败）。

## 10. 网格尺寸与 mod

- **网格尺寸不存于存档文件**：`.d2s` 只存物品的页与坐标，没有尺寸字段；尺寸来自游戏数据。core 现状 `GRID_SIZE` 为写死的原版值（背包 10×4 / 个人与共享仓库 10×10 / 方块 3×4）。
- mod 扩大背包/仓库时，app 须：① **按该页实际物品坐标推断最小尺寸**（如有物品 y+h = 6 则背包至少 10×6，布局按推断值扩）；② 推断值向上套预设档位；③ 设置页留手动指定尺寸的入口（后续版本）。
- 解析层读坐标无障碍，受影响的只有布局/放置常量——实现时把 `GRID_SIZE` 改为"推断 + 预设"的动态来源，UI 按实际行列渲染并配合一屏固定原则（行数变多时格子等比缩小）。
- **实测（2026-10-21，用户实况存档）**：D2R Mobile 自带大仓库 mod，David（Lv12 术士）`.d2s` 个人仓库 2 件物品坐标 extent = **14 列 × 10 行**（珠宝位于 x=13、y=9），与游戏截图量出的 14 列一致——坐标推断法成立，原版 10×10 假设会切掉 4 列物品，动态尺寸是硬需求。原型 v3 已按此渲染：14 列时格宽 25px（标准 28px 适用于 ≤12 列）。空页（如该 mod 的 5 页签个人仓在文件中只有一页坐标）推断不出，仍需预设档位 + 设置页手动覆盖兜底。另实测游戏自身格宽 ≈21pt（15 Pro 横屏截图量测），28px 基准留有余量、无需再缩。

## 11. 导入 / 导出流程

### 11.1 导入（入口：角色页 / 仓库页 / 宝库页）
1. 系统文件选择器选 `.d2i`（document picker）。
2. 导入 Sheet：物品预览（名/品质/类型）+ 数量步进（可堆叠）+ 目标选择（宝库 / 背包 / 个人仓库 / 共享仓库，默认跟随入口页）+ fit 提示（宝库"无限追加"；网格"自动找位，放不下会提示"，对应 `First-Fit-Decreasing + findSpot`）。
3. 确认 → Toast。解析用 `core.parseImportFile` + `planImport`。

### 11.2 导出（物品面板 → 导出 .d2i）
- `export_item` 写 `Documents/exports/`（已实装），Toast 提示位置，用户经文件 App 挪入 D2R Mobile 文件夹。字节流走现有 `itemBytes`。

## 12. 数据模型要点（UI 必须尊重）

- **vault 无坐标**：`Vault.entries` 是数组（`{uid, item, addedAt, source}`）；格子只存在于存档侧，物品离开 vault 时才由放置算法定格。托盘同为此模型。
- **装备槽**：bodyLoc（头 1 / 颈 2 / 躯干 3 / 右手 4 / 左手 5 / 戒 6,7 / 腰带 8 / 脚 9 / 手套 10 / 副手 11,12）；娃娃槽位与之 1:1。
- **腰带**：药水格 0–15（最下排优先），可用格数 = 所穿腰带 `beltBoxes`（4/8/12/16），无腰带时 4。
- **佣兵**：上游已支持（`d2s.ts` 解析、`core/merc.ts` 规则、桌面 `MercPanel`）；显示条件沿用桌面（`ch.mercSplit || ch.mercItems.length > 0`）。
- **金币分池**：共享仓库 RotW 为全页签一池；宝库按版本 × HC/SC 分池（`goldPot`），不跨池混显。

## 13. 美术资源（物品图标）

- 目标：游戏内 HD sprite（`hd/global/ui/items/*.sprite`，SpA1），**必须来自用户自己购买的游戏文件**（CascView 解包），自用侧载，绝不进分发包。
- 移动端：新增 `ArtBackend` 读 App Documents 下资源包，纯 TS `decodeSprite` 在 webview 内解码；无资源时降级 glyph 图标，UI 不变。
